# Master Prompt — Arbitrum Builder Labs Project

You are my lead product designer, senior frontend engineer, Web3 educator, QA engineer, and GitHub release manager.

We are building my **Arbitrum Builder Labs assignment** as a polished, original, evaluator-focused project.

Your goal is NOT to make a basic four-page student website.

Your goal is to build a website that makes the evaluator immediately think:

> "This person understood the assignment, understood the Web3 concepts, and knows how to turn them into a real interactive product."

The final project must be technically correct, visually distinctive, responsive, fast, well-organized, and easy for me to explain during evaluation.

---

# 1. ASSIGNMENT REQUIREMENTS — NON-NEGOTIABLE

The final website must contain exactly these four primary pages:

1. Home / Landing
2. Concepts
3. Live Prices
4. Block Simulator

All four pages must be part of ONE cohesive website.

Every page must have a shared navigation system.

The visitor must be able to navigate to every page from every page without manually editing the URL.

The active page must be visually highlighted.

The website must be responsive on desktop, tablet, and mobile.

The assignment allows HTML/CSS/JavaScript or React/Next.js. Use React + TypeScript + Vite unless there is a strong technical reason not to.

Use clean component architecture.

# 8. PAGE 4 — BLOCK SIMULATOR

This is the most technically important page.

Implement it using JavaScript/TypeScript and the Web Crypto API where practical.

Do NOT use a blockchain library.

The page must demonstrate:

* Block data
* Previous hash
* Nonce
* Hashing
* Simulated proof-of-work
* Block validity
* Chain dependency
* Immutability

## BLOCK 1

Inputs:

Block Data
Previous Hash
Nonce

Show:

Current Hash
Mining status
Validity

## MINING

Create a "Mine Block" button.

When clicked:

* Start from the current nonce
* Increment nonce
* Generate a SHA-256 hash
* Continue until the hash begins with "00"
* Display the successful nonce
* Display the resulting hash
* Show that the block is valid

Make the mining process visually understandable.

Show something like:

MINING...

Nonce: 184
Hash: 8f92...

Nonce: 185
Hash: 4a10...

Nonce: 186
Hash: 00b71...

BLOCK MINED

Do not fake the final result.

Actually calculate it.

## BLOCK 2

Block 2 must use Block 1's hash as its Previous Hash.

Visually connect:

BLOCK 01
↓
BLOCK 02

Block 2 must become invalid if Block 1's data changes.

## TAMPERING DEMONSTRATION

Provide a clear interaction:

"TAMPER WITH BLOCK 01"

When Block 1's data changes:

1. Block 1 hash changes
2. Block 2 previous hash no longer matches
3. Block 2 becomes INVALID

Make the transition visually obvious.

Display:

CHAIN INTEGRITY
COMPROMISED

Then explain briefly:

"Changing earlier data changes its hash, breaking the reference stored by the next block."

This is the key educational insight.
